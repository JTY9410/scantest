## 1. Requirement B: ML Scheduler Architecture (PRODUCTION BLOCKER - RESOLVED)

### Environment Variables (Default OFF - Opt-In)

- **`ML_SCHEDULER_ENABLED`** (default: `false`)
  - Enables ML retraining scheduler (daily at 03:00 KST + every N new rows)
  - Uses PostgreSQL advisory lock (`pg_try_advisory_lock(12345)`) for single-host execution
  - Never runs in `TESTING` mode

- **`ML_AUTO_BACKFILL`** (default: `false`)
  - Enables automatic feature backfill on application startup
  - Runs batched (100 scans/batch), non-blocking background thread
  - Never runs in `TESTING` mode

- **`ML_RETRAIN_EVERY_N`** (default: `20`)
  - Trigger retraining after N new feature rows
  - Requires `ML_SCHEDULER_ENABLED=true`

### CLI Commands

```bash
# Extract ML features for existing scans (batched, idempotent)
flask ml backfill --batch-size 100

# Manually trigger ML model retraining
flask ml retrain

# Show ML system status
flask ml status
```

### Documentation

- `docs/ML_SCHEDULER_SETUP.md`: Complete setup guide with 3 deployment scenarios
  1. Manual CLI (cron-based)
  2. In-process scheduler (single-server)
  3. Dedicated worker service (recommended for production)

## 2. SQLite Compatibility Fixes (TEST SUITE IMPROVEMENTS)

### Root Cause: PostgreSQL-Specific SQL Functions

The test failures were caused by PostgreSQL-specific SQL syntax not compatible with SQLite:

1. **`NOW()` function** → Replaced with `CURRENT_TIMESTAMP` (73 occurrences)
   - Files: `app/modules/scanner/continuous_learning.py`, `app/cli.py`, `migrations/versions/24a5625b25e7_*.py`, multiple test files
   
2. **`UPDATE...FROM` syntax** → Conditional query based on database type
   - File: `app/cli.py` (`recover-destroyed-makers` command)
   - PostgreSQL: keeps `UPDATE...FROM` syntax
   - SQLite: uses `UPDATE...WHERE source_id IN (SELECT ...)` subquery

3. **`LEAST()` / `GREATEST()` functions** → Replaced with `MIN()` / `MAX()`
   - File: `app/modules/scanner/continuous_learning.py`

4. **Missing SQLite test schema tables**
   - Added: `maker_aliases`, `command_stats`, `learning_runs`, `battery_reference_capacity`, `vin_decode_rules`, `ml_model_runs`, `ml_active_model`, `ml_consistency_scores`, `label_change_history`
   - File: `tests/conftest.py`

### Test Results

- **Key v2.2.9 features:** 4/4 passed (`test_ml_feature_extraction`, `test_upload_multikey`, `test_tesla_version_footer`)

## 3. Battery Reference Capacity System (D.1-D.5)

### Database Schema

**Table:** `battery_reference_capacity`

Comprehensive master data columns:
- Vehicle identification: `maker`, `model`, `trim`, `generation`, `year_from`, `year_to`
- Tesla-specific: `vin_wmi`, `vin_factory`, `pack_id`
- Capacity values: `official_capacity_kwh`, `gross_capacity_kwh`, `net_capacity_kwh`, `rated_voltage_v`, `rated_capacity_ah`, `computed_capacity_kwh`
- Classification: `official_classification` (총용량/사용가능/공표)
- Verification: `verification_level`, `domestic_sales_verified`, `domestic_application_evidence`
- Sources: `source_url_1`, `source_url_2`, `source_id`
- Cell details: `cell_manufacturer`, `chemistry`, `pack_type_note`
- Notes: `notes`, `warnings`

**Migration:** `20261116_140000_add_comprehensive_battery_reference.py`

### Data Import

```bash
# Import battery reference data from xlsx files
flask battery-ref-import data/battery_reference/import7_brands_capacity_master.xlsx

# Clear existing data before re-import
flask battery-ref-import --clear path/to/file.xlsx
```

**Master Data Files:**
- `data/battery_reference/import7_brands_capacity_master.xlsx`: VW, MINI, Volvo, Jaguar, Land Rover, Jeep, Maserati (gross/net/rated V×Ah, official sources)
- `data/battery_reference/tesla_vin_pack_db.xlsx`: Tesla pack candidates (PKxxx), 연식별 목록, VIN code table, 공식 국내정격 (V×Ah)

### Matching Logic (D.3)

**Module:** `app/modules/scans/battery_soh.py`

1. **Required:** `maker` + `model`
2. **Optional:** `year` (must be within `year_from`/`year_to` range)
3. **Optional:** `trim` (exact match)
4. **Tesla VIN decoding:** WMI pattern match (`vin[:3]`)

### Multi-Candidate Handling (D.3)

- If multiple pack candidates match (e.g., Tesla 2021 Model Y LR: 75 kWh vs 82.1 kWh):
  - **Does NOT auto-select**
  - Returns all candidates with metadata
  - Status: `'팩 후보 다수 — 팩ID 확인 필요'`
  - SOH: Not calculated until admin selects pack ID
  - Candidate list includes: `pack_id`, `trim`, `capacity_kwh`, `verification_level`, `year_range`

### SOH Calculation Rule (D.4)

**Like-for-Like Comparison Only:**

| Current Capacity Type | Reference Type Required | SOH Calculation |
|-----------------------|-------------------------|-----------------|
| Gross (총용량)         | `gross_capacity_kwh`    | ✅ (current / ref) × 100 |
| Net (사용가능)         | `net_capacity_kwh`      | ✅ (current / ref) × 100 |
| **Gross vs Net**      | **Mismatched**          | ❌ `미산정` (cannot compare) |

**Never:** Divide usable by gross (apples-to-oranges comparison)

### Report Display (D.5)

**Labels:**
- Official source → `'제조사 공표 기준'`
- Secondary source (ev-database, etc.) → `'2차 자료 기준(참고)'`

**Displayed Information:**
- **기준용량:** Value (kWh), classification (Gross/Net/공표), source, verification level
- **현재용량:** Current measured capacity
- **SOH(기준용량 대비):** Percentage with source label

**Example:**
```
기준용량: 74.0 kWh (총용량, 제조사 공표 기준, 검증 수준: 높음)
현재용량: 65.26 kWh
SOH(기준용량 대비): 88.2% (제조사 공표 기준)
```

### Tesla Multi-Upload Example
