# 운영 가이드: 명령어 검증 및 승격

## 개요

제조사별 OBD2/UDS 명령어와 해석 수식은 처음에 `experimental` 상태로 추가됩니다.
실제 차량에서 검증이 완료되면 `verified` 상태로 승격하여 모든 스캔에서 사용할 수 있게 됩니다.

## 상태 종류

- **draft**: 초안 (내부 검토 중)
- **experimental**: 실험 단계 (제한적 사용, 라벨 표시)
- **verified**: 검증 완료 (모든 스캔에서 자동 사용)
- **deprecated**: 사용 중단 (더 이상 사용 안 함)

## 승격 절차

### 1. 실차 검증

experimental 명령어를 실제 차량에서 테스트:

1. 해당 제조사/모델 차량 준비
2. 명령어 실행 및 응답 확인
3. 응답값이 예상 범위 내인지 확인
4. 여러 차량에서 재현성 확인 (가능한 경우)

### 2. 검증 근거 기록

다음 정보를 기록:
- **차량 정보**: 제조사, 모델, 연식
- **VIN** (차대번호): 검증에 사용한 차량
- **테스트 날짜**: 2026-10-24
- **테스터**: 검증을 수행한 사람
- **결과**: 응답값 예시 및 정상 여부

예시:
```
현대 코나 EV 2023년식, VIN: KMHK381CBPU123456
2026-10-24 테스트, 테스터: 김정비
명령어 22B001 응답: 00 01 86 A0 (10,000 km) - 정상
```

### 3. CLI로 승격 실행

터미널에서 Flask CLI 명령어 실행:

#### 특정 명령어 승격
```bash
flask kb promote --command 22B001 --maker 현대 --evidence "VIN KMHK381CBPU123456, 2026-10-24 검증 완료"
```

#### 특정 수식 승격
```bash
flask kb promote --formula-id 5 --evidence "현대 코나 EV 실차 테스트 완료"
```

#### 모든 experimental 항목 일괄 승격
```bash
flask kb promote --all-experimental --evidence "2026-10-24 실차 테스트 일괄 검증"
```

### 4. 결과 확인

승격 후 다음 사항 확인:

1. 데이터베이스에서 상태가 `verified`로 변경되었는지 확인
2. `promotion_log` 테이블에 감사 기록이 남았는지 확인
3. 스캔 결과에서 해당 명령어가 자동으로 사용되는지 확인

## 강등 (Rollback)

문제가 발견된 경우 다시 experimental로 강등:

```bash
flask kb demote --command-id 123 --reason "응답값 불안정, 재검증 필요"
```

```bash
flask kb demote --formula-id 45 --reason "해석 공식 오류 발견"
```

## 주의사항

### 승격 전 확인사항

- [ ] 최소 1대 이상의 실차에서 테스트 완료
- [ ] 응답값이 예상 범위 내에 있음
- [ ] 다른 명령어와 충돌하지 않음
- [ ] 검증 근거가 명확히 기록됨

### 승격 후 모니터링

- **첫 1주일**: 해당 명령어가 포함된 스캔 결과 모니터링
- **오류 발생 시**: 즉시 강등 및 원인 분석
- **정상 작동 확인**: 검증 완료 표시 유지

## 감사 기록 (Audit Trail)

모든 승격/강등은 `promotion_log` 테이블에 자동 기록됩니다:

- **누가** (promoted_by): 승격을 실행한 사용자
- **언제** (promoted_at): 승격 시각
- **무엇을** (entity_type, entity_id): 명령어 또는 수식 ID
- **어떻게** (old_status → new_status): 상태 변경
- **왜** (evidence): 검증 근거
