# 블루투스 OBD2 연결 프로필

모바일 앱이 블루투스 OBD2 진단기(ELM327·STN 계열)에 연결할 때 쓰는 설정을 관리자가 등록하고, 앱은 로그인 후 받아 갑니다. 서버는 진단기에 직접 연결하지 않습니다.

| 사용자 행동 | route | service (`obd/service.py`) | 저장 | 결과 |
| --- | --- | --- | --- | --- |
| 프로필 목록 | `GET /admin/obd/` | `list_profiles` | - | 연결 방식, 기기 이름, BMS 헤더, 조회 명령 수, 제공 여부 |
| 등록·수정 | `POST /admin/obd/new`, `/admin/obd/<id>/edit` | `save_profile` | 프로필, 감사기록 | 목록으로 이동. 버전이 다르면 409 |
| 앱이 설정 받기 | `GET /api/obdProfiles` | `enabled_profiles` | - | "앱에 제공"이 켜진 프로필만 camelCase로 |

## 입력 규칙

- 연결 방식: BLE(저전력, iPhone·Android) 또는 클래식 SPP(Android 전용). BLE는 서비스·쓰기·알림 UUID 세 개가 모두 있어야 하고, 클래식은 UUID를 저장하지 않습니다.
- UUID는 `FFF0` 같은 4자리 또는 128비트 형식이며 소문자로 저장합니다.
- 초기화 명령은 `AT`/`ST`로 시작하는 줄만 받고, 조회 명령은 16진수 바이트(1~7바이트)만 받습니다. 둘 다 공백을 지우고 대문자로 저장하며 최대 50줄입니다.
- 요청·응답 헤더(CAN ID)는 3자리(11비트) 또는 8자리(29비트) 16진수이고, 둘을 함께 입력해야 합니다.
- 프로필은 지우지 않고 "앱에 제공"을 꺼서 중지합니다.
- 조회 명령에는 검증된 항목만 넣습니다. 차종별 DID 확정은 CAN 역분석(`docs/flows/canlab.md`)의 결과를 따릅니다.

## 프로필 없이 연결

프로필은 선택 사항입니다. 웹(대시보드·수집 페이지)은 진단기 이름·서비스로 찾고 응답하는 채널을 자동으로 고릅니다(`docs/flows/canlab.md`의 "블루투스 진단기 연결"). 프로필은 특정 진단기의 UUID·초기화 명령을 고정할 때 씁니다.

## 앱 자동 연결

모바일 앱(`wecar_scan`, `BleConnectService`)은 한 번 연결한 진단기(`remoteId`, 이름)를 기억합니다. 기억한 진단기가 있으면 앱 시작부터 45초마다 15초씩 찾아서, 시동을 켜고 진단기 전원이 들어오면 자동으로 연결합니다. 사용자가 연결을 끊으면 다시 스캔할 때까지 멈추고, 연결 화면의 "기억 지우기"로 기억을 지웁니다.

## 진단기 명령

스캔 계획(`docs/flows/scanner.md`)을 보내기 전후에 웹(`obd-link.js`, `obd-scan.js`)과 앱(`ble_connect_service.dart`, `obd_plan.dart`)이 진단기에 보내는 명령입니다.

| 때 | 명령 | 이유 |
| --- | --- | --- |
| 연결 직후 | `ATZ`, `ATE0`, `ATL0` | 초기화, 에코·줄바꿈 끄기 |
| 형식 | `ATH1`, `ATS1`, `ATCAF1`, `ATAT1`(웹만) | 응답 주소·공백을 붙여 받고 ISO-TP 형식 맞춤, 대기 시간 자동 조절 |
| 칩 확인(웹) | `ATI`, `STDI`(STN 계열, `?`면 무시), `ATRV` | 진단기 종류, 전압 |
| 통신 방식 | `ATSP0`, 웹은 기억한 방식이 있으면 `ATSPA<n>` | 첫 `0100`은 30초까지 기다리고, 웹은 찾은 방식을 진단기별로 기억 |
| 제어기 주소 | `ATSH`·`ATCP`·`ATCRA` | `docs/flows/scanner.md`의 "스캔 계획" 주소 규칙 |

- 명령은 한 번에 하나씩 보냅니다. 쓰기 직전에 받은 버퍼를 비우고, 시간이 지난 뒤 늦게 온 응답은 다음 명령 응답에 넣지 않습니다.
- 앱은 응답 줄바꿈을 지우지 않고 공백으로 바꿔 ECU별 응답이 붙지 않게 하고, BLE 쓰기 특성은 `write`·`writeWithoutResponse` 중 하나만 있어도 씁니다.

### 오류 복구

진단기 오류는 각각 한 번만 복구해 다시 보냅니다(웹 `obd-plan.js`의 `recovery`, 앱 `ObdPlan.recovery`가 같음).

| 응답 | 복구 |
| --- | --- |
| `STOPPED` | 다시 보냄 |
| `BUFFER FULL`, `RX ERROR`, `DATA ERROR` | `ATS0`(공백 없이 받아 버퍼 절약)으로 다시 보낸 뒤 `ATS1` |
| `CAN ERROR`, `BUS INIT…`, `BUS ERROR` | `ATPC`(프로토콜 닫기) 후 다시 보냄 |
| `7F xx 78`(응답 대기)만 받음 | `ATSTFF`로 대기 시간을 늘려 5초 이상으로 2회까지 다시 보낸 뒤 `ATST32` |
| `7F xx 21`(사용 중)만 받음 | 200ms 뒤 다시 보냄 |
| `NO DATA`, 시간 초과 | 복구하지 않음. 그 제어기의 첫 요청(`22F190`)이면 나머지 요청을 건너뜀 |

## 지원 진단기

ELM327 명령을 받는 진단기는 연결 방식과 관계없이 씁니다. 웹은 BLE·블루투스 클래식·USB, 앱은 BLE·블루투스 클래식(Android)·WiFi를 지원합니다. 방식별 차이는 `docs/flows/scanner.md`의 "연결 방식"을 봅니다.
