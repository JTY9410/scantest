# OBD2 스캔하기

관리자가 차량번호로 차량 정보를 조회하고, 진단기로 차량 전체를 스캔해 위스캔 결과 형식으로 보여 줍니다. 화면은 관리자 메뉴 "진단 스캔 > 스캔하기"(`/admin/scan/`)와 대시보드의 "블루투스 진단기" 카드입니다. 웹·모바일 앱·LTE 단말기가 같은 계획과 해석을 씁니다.

순서: 시동 → 진단기 연결 → 스캔하기 → 차량번호 조회 → 차량 스캔 → 분석 결과(저장·PDF). 화면 위쪽 단계 표시(`scanner/_flow.html`)가 지금 단계와 실패 단계를 보여 줍니다.

- 블루투스 연결은 페이지마다 따로입니다. 대시보드의 "스캔하기"는 다른 화면으로 이동하지 않고 같은 카드의 연결로 스캔합니다(이동하면 연결이 끊겨 스캔할 수 없음).
- 진단기가 연결되지 않은 채 "스캔하기"를 누르면 진단기 선택 창을 띄우고 연결 단계를 실패로 표시합니다.
- 차량정보 조회 인증키가 없으면 흐름 위에 "설정 > 차량정보 조회" 안내를 보여 줍니다. 조회에 실패해도 "조회 없이 스캔 계속"으로 스캔할 수 있습니다.

| 사용자 행동 | route | service (`scanner/service.py`) | 저장 | 결과 |
| --- | --- | --- | --- | --- |
| 스캔하기 화면 | `GET /admin/scan/` | `obd_config`, `flow_config` | - | 진단기 연결 패널, 스캔 흐름 |
| 차량번호 조회 | `POST /admin/scan/lookup` | `lookup_car` (`carinfo`) | 조회 캐시, 실패 시 감사기록 "차량정보 조회 실패" | 차량 정보. 실패하면 `{message, kind, detail}`와 안내 |
| 스캔 계획 받기 | `POST /admin/scan/plan` | `build_plan` (`scanner/plan.py`) | - | 명령 단계 목록과 안내 |
| 스캔하기 | 브라우저가 단계별로 진단기에 전송 (`static/js/components/obd-scan.js`) | - | - | 진행률, 단계별 성공·오류 수 |
| 결과 저장 | `POST /admin/scan/run` | `run_scan` | 통신 기록(`live_capture`), 결과지, 스캔·스캔 코드, 결과 PDF(`scan_documents`), 감사기록 | 201 `{id, status, url}` 후 결과 화면(`?pdf=1`)으로 이동하며 PDF를 내려받음 |
| 결과 보기 | `GET /admin/scan/<id>` | `scan_result` | - | 위스캔 결과 형식. 운영 데이터 스캔 상세의 "위스캔 결과" 버튼도 이 화면 |
| PDF 내려받기 | `GET /admin/scan/<id>/pdf` | `scan_document` (`scanner/pdf.py`) | 없으면 지금 만들어 저장 | A4 PDF. 결과 화면 "PDF 내려받기", 스캔 상세 "결과 PDF" |

## 스캔 계획 (`scanner/plan.py`)

1. 진단기: `ATRV`(전압), `0100`(통신 확인), `ATDPN`(프로토콜).
2. OBD2(J1979): 지원 PID(`0120`~`01A0`), 모니터 상태(`0101`), 실시간 값 약 50개(연료 계통, 연료 보정, 산소센서, 촉매 온도, 연료 소비율 등), VIN·캘리브레이션 ID·ECU 이름·CVN(`0902`, `0904`, `090A`, `0906`), 고장코드(`03` 확정, `07` 대기, `0A` 영구), 고장 당시 값(프리즈 프레임, `020200`과 `02xx00`).
3. UDS(CAN 차량만): 위카 앱과 같은 기능 주소 고장코드 조회(`190209`, `190204`, `1915`). 제어기 `7E0`~`7E7`에 `22F190`(VIN)으로 응답 여부를 확인한 뒤 `1902FF`(고장코드), `22F187`(부품번호), `22F195`(소프트웨어 버전). 현대·기아는 BMS·계기판 등 제조사 제어기를 더합니다.
4. 현대·기아 전기·하이브리드·수소차: BMS(`7E4`)의 `220101`, `220105`(구형은 `2101`, `2105`).
5. CAN 분석에서 적용한 규칙의 요청(`capture_requests`)을 계획에 없는 것만 더합니다.

- 브라우저는 `0100`·`0120`… 지원 비트맵에 없는 PID를 보내지 않고 "지원 안 함"으로 기록합니다. 저장된 고장코드가 없으면(`0101`) 프리즈 프레임을 건너뜁니다.
- 응답 없는 제어기의 나머지 UDS 요청은 건너뜁니다. K-Line·J1850 차량은 UDS를 하지 않습니다.
- 위카 앱(`wecar_scan`)의 스캔 명령: 초기화 `AT Z`, `AT E0`, `AT H1`, `AT SP 0` → VIN `09 02`(안 되면 `22 F1 90`) → 고장코드 `03`, `07`, `0A`, `19 02 09`, `19 02 04`, `19 15` → 전기차 `22 01 01` → CAN 수집.
- 29비트 CAN은 `ATCP18`+`ATSH DB33F1`, 11비트는 `ATSH 7DF`(또는 제어기 헤더)를 씁니다.
- DoIP(이더넷 진단)는 ELM327 계열 진단기로 접근할 수 없어 결과에 안내만 남깁니다.

## 해석 (`scanner/interpret.py`, `scanner/obd.py`)

- 응답을 `# WECAR-ELM 1` 통신 기록으로 바꿔 CAN 분석 엔진(ISO-TP 결합, UDS 짝짓기, 적용 규칙)으로 해석합니다.
- 결과: 프로토콜, 전압, VIN(OBD·UDS 출처), 모니터 상태, 실시간 값, 고장 당시 값(`freeze_frame`), 고장코드(현재·확정·대기·영구, 제어기, 시스템), 제어기 목록(부품번호·소프트웨어 버전), CVN, 배터리 값.
- PID 공식은 SAE J1979 공개 정의를 따릅니다(GPL 라이브러리 코드는 쓰지 않음).
- 고장코드는 진단 코드 DB의 설명·원인·조치를 붙입니다.
- 배터리 값은 적용 규칙이 있으면 규칙 값, 없으면 공개 자료 기준의 "참고 해석(미검증)"으로 표시합니다.

## 오류 기록

모든 단계의 결과를 저장하고, 결과 화면의 "오류 기록"과 "전체 단계"에 보여 줍니다. 스캔이 실패해도 저장합니다.

| 상태 | 뜻 |
| --- | --- |
| 성공·지원 안 함·건너뜀 | 오류가 아님. 선택 단계의 응답 없음·부정 응답, 지원 PID에 없는 항목은 "지원 안 함" |
| 응답 없음 | `NO DATA` |
| 부정 응답 | UDS `7F` (사유 코드 표시) |
| 시간 초과 | 진단기가 응답하지 않음 |
| 연결 끊김 | 진단기·차량 연결이 끊김(20초 안에 다시 연결되면 이어 감) |
| 단말기 오류 | `CAN ERROR`, `BUS INIT ... ERROR`, `?` 등 진단기 오류 |
| 해석 오류 | 응답을 해석하지 못함 |
| 서버 오류 | 해석 중 예외. 받은 응답은 그대로 저장 |
| 조회 실패 | 차량정보 조회 실패(인증키 없음, 한도 초과 등) |
| 화면 오류 | 브라우저에서 스캔이 중간에 멈춤. 그때까지 받은 단계는 저장 |
| PDF 오류 | 결과 PDF를 만들지 못함. 스캔은 저장되고 "PDF 내려받기"에서 다시 만듦 |

- 전체 상태: 성공(오류 없음), 일부 성공(오류 있음), 실패(OBD 응답 없음).
- 차량정보 조회 실패는 오류 기록 첫 줄에 남기고 스캔은 계속합니다.
- 결과 저장이 네트워크 문제로 실패하면 화면의 "저장 다시 시도"로 같은 결과를 다시 보냅니다.

## 결과 PDF (`scanner/pdf.py`)

- reportlab(BSD)과 나눔고딕(SIL OFL, `scanner/fonts/`)으로 A4 PDF를 만듭니다. 차량·검사 정보, 진단 요약, 고장코드, 고장 당시 값, 배터리, 실시간 값, 제어기, 오류 기록을 담습니다.
- 스캔을 저장할 때 같은 트랜잭션에서 `scan_documents`에 저장합니다(스캔당 1개). 파일 이름은 `위스캔-<차량번호>-<YYYYMMDD-HHMM>.pdf`입니다.

| BLE | Web Bluetooth | `flutter_blue_plus` | Vlinker, OBDLink, Veepeak, Carista 등 이름·서비스로 찾기, "모든 기기 보기" |
| 블루투스 클래식(SPP) | Web Serial(Chrome 117 이상, 페어링 후 "블루투스 클래식·USB") | Android `flutter_classic_bluetooth` | 38400·9600·115200·500000 bps 순서로 연결 |
| USB | Web Serial | - | |
| WiFi | 지원 안 함(브라우저가 TCP 연결 불가) | 소켓 `192.168.0.10:35000` | 앱 연결 화면 WiFi 탭 |
| LTE 단말기 | - | - | 서버 API로 계획 받기·결과 올리기 (`docs/flows/telematics.md`) |
